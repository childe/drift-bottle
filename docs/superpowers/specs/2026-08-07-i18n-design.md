# 漂流瓶 · 界面多语言（i18n）设计

日期：2026-08-07
状态：已与产品负责人逐点确认
前置：MVP 已上线（https://drift-bottle.rmself.workers.dev），本设计是其增量功能

## 1. 目标与范围

让全球用户能用自己的语言使用界面。

**做**：所有面向用户的**界面文案**多语言（按钮、提示、面板标题、弹窗、错误提示）。首批中文 + 英文，架构支持随时增补语言。

**不做（明确排除）**：
- 用户信件内容**不翻译**（漂流瓶飘到异国，捡瓶人看到的是原文——保留漂流瓶的"陌生与神秘"）
- 内容审核的多语言能力（Llama Guard 3 官方不支持中文，全球化会放大此短板）——**搁置为 backlog**，界面 i18n 上线后单独处理

## 2. 语言资源

新建 `web/public/i18n.js`，纯前端字典 + 取词函数，被 `index.html` 与 `track.html` 共享：

```js
const I18N = {
  zh: { drop_btn: "写一封信，投进大海", nearby_title: "附近搁浅的瓶子", ... },
  en: { drop_btn: "Write a letter, cast it to sea", nearby_title: "Beached bottles nearby", ... },
};
// 取词：缺 key 回退英文，再缺回退 key 本身（永不显示空白/undefined）
function t(key, lang) {
  return (I18N[lang] && I18N[lang][key]) || (I18N.en && I18N.en[key]) || key;
}
```

**key 覆盖范围**：现散落在 `index.html` / `app.js` / `track.html` / `track.js` 中的全部中文串抽成 key。含：静态 UI（标题、按钮、占位符、提示）、JS 动态拼接文案（"漂了 N 天"、"入海点距你 X km"、"瓶中信（N 封）"等——带参数的用占位符如 `letters_count: "瓶中信（{n} 封）"`，`t()` 之外用简单 `.replace("{n}", n)`）、以及 API 错误的 code→文案映射（见第 4 节）。

## 3. 语言选择与切换（自动检测 + 手动切换）

**决定当前语言**（`resolveLang()`）：
1. `localStorage.lang` 若存在且受支持 → 用它
2. 否则看 `navigator.language`：以 `zh` 开头 → `zh`，其余 → `en`
3. 兜底 `en`

**手动切换**：两个页面顶部放一个轻量切换控件（`中 / EN` 文字按钮）。点击 → 写 `localStorage.lang` → 调 `applyI18n()` 即时重渲染当前页（无需刷新）。

**渲染机制**：
- 静态文案：HTML 元素加 `data-i18n="key"`（文本）与 `data-i18n-ph="key"`（输入框 placeholder）属性；`applyI18n(lang)` 遍历这些元素用 `t(key,lang)` 填充；同时设置 `<html lang>`。
- 动态文案：JS 生成内容处，把硬编码中文换成 `t(key, currentLang)`（+ 占位符替换）。`currentLang` 为模块级变量，切换时更新。
- 页面加载末尾调用一次 `applyI18n(resolveLang())`。

## 4. API 错误的国际化（前端映射，后端英语化）

**后端**：`web/src/index.ts` 的 `err()` 消息一次性**改为英语**，作为 API 默认语言（利于日志/调试/第三方直调/兜底）。错误结构 `{error:{code,message}}` 不变，`code` 保持稳定（`bad_content`/`bad_coords`/`no_ocean`/`not_found`/`too_far`/`already_picked`/`rejected`/`moderation_unavailable`）。**后端从此不掺和 i18n**。

**前端**：i18n 字典含 `err_<code>` 系列 key（zh/en 各一份）。前端 `api()` 包装拿到错误后，优先按 `err_<code>` + 当前语言查表显示；**查不到时** fallback 显示后端返回的英语 `message`（兜底，保证永不空白）。

用户实际看到的错误永远是当前界面语言；后端英语 message 仅在前端漏映射时兜底露出。

## 5. 文件影响

- **新增** `web/public/i18n.js`：`I18N` 字典、`t()`、`resolveLang()`、`applyI18n()`、`currentLang` 状态、切换处理
- **改** `web/public/index.html`：引入 i18n.js（在 app.js 之前）、静态串加 `data-i18n`、加语言切换控件
- **改** `web/public/app.js`：动态中文串改 `t()`；接入切换后重渲染；错误按 `err_<code>` 映射
- **改** `web/public/track.html`：引入 i18n.js、静态串加 `data-i18n`、加切换控件
- **改** `web/public/track.js`：动态中文串改 `t()`
- **改** `web/src/index.ts`：`err()` 各处 message 中文→英语（code 不变）；相关测试断言若查中文 message 需同步（大多数断言查 status/code，不查 message 文本）

## 6. 测试

- **i18n.js 纯函数**（vitest，Node 环境）：`t()` 命中、缺 key 回退英文、连英文都缺回退 key 本身；`resolveLang()` 对 `zh-CN`/`en-US`/`fr`/空 的判定；占位符替换正确
- **后端**：既有 30 个测试须保持通过（改英语 message 后，凡断言中文 message 文本的用例同步改为断言英语或改断言 code）
- **前端冒烟**（部署后）：中英切换即时生效、刷新后保持（localStorage）、投瓶被拒时错误按当前语言显示

## 7. 部署

前端为静态资源，`wrangler deploy` 即可；后端 `err()` 改动随同一次 deploy。无 schema 变更、无新环境变量、无新依赖。

## 8. 明确不做（backlog）

- 审核多语言（Llama Guard 中文/多语言短板）
- 信件内容翻译
- 3 种及以上语言（架构已支持，按需增补字典即可）
- 语言的 SEO / `hreflang` / 服务端按 `Accept-Language` 协商
